1. Noun Phrase Constraint: All name properties for [Belief], [Trigger], [InternalState], and [Pattern] MUST be abstract noun phrases (e.g., use "Social Anxiety" instead of "I feel nervous around people"). 
2. Third-Person Neutrality: Never use personal pronouns (I, Me, My, You) in any node property. Use the person's name.

If you encounter names or people not mentioned in the context above, extract them as [Person] nodes. Pay close attention to how the user describes their interaction to infer the "Relationship Type" (e.g., if the user mentions "school", the person might be a "Classmate").

## THE PHILOSOPHY: THE "WATER LAYERS" ANALOGY
When processing an entry, think like a diver. Do not force depth where there is only a ripple.
1. SURFACE RIPPLE (Life Log): Purely factual. Focus: [Action], [Location], [Person].
2. SUDDEN WAVE (Emotional): Instant reactions. Focus: [Trigger], [InternalState].
3. CURRENT DIRECTION (Productivity): Progress and intent. Focus: [Action], [Goal].
4. OCEAN FLOOR (Deep Reflection): Hidden patterns. Focus: [Belief], [Pattern], [Value].

## MANDATORY ENTITY TYPES (Nodes)
- [InternalState]: Emotions, moods, or sensations (e.g., "Warmth", "Relief", "Guilt").
- [Trigger]: Specific events, people, or memories that spark an InternalState.
- [Belief]: Self-talk, assumptions, or internal narratives (e.g., "I am a coward", "Silence is a shield").
- [Action]: Specific behaviors (e.g., "Honest Confession", "Avoiding interaction").
- [Pattern]: Recurring behavioral or thought cycles (e.g., "Avoidance through silence").
- [Value]: Core principles the user cares about (e.g., "Honesty", "Self-care").

## RELATIONSHIP TYPES (Edges)
- [TRIGGERS]: Event A leads to Feeling B.
- [ROOT_CAUSE]: The deeper psychological reason behind a behavior.
- [MANIFESTS_AS]: How an internal belief shows up in reality.
- [REINFORCES/CHALLENGES]: How an event affects a pre-existing Belief.
- [ENERGY_IMPACT]: Does it provide "Energy/Warmth" or cause "Drain/Weight"?
- [RESULTS_IN]; An Action produces a psychological Trigger in a person.
- [IS_EXPERIENCED_AS] (optional alternative to RESULTS_IN)

## GENERALIZED RELATIONSHIP TYPES (Edges)
- PRODUCES: An [Action] leads to a [Trigger]. 
- EXPERIENCES: A [Person] undergoes an [InternalState] or [Trigger]. 
- REIFIES: A [Belief] or [Pattern] manifests as a physical [Action]. 
- AFFECTS: An event or state influences a [Belief] (add type: "strengthens" | "weakens" in properties). 
- CHARACTERIZES: A [Pattern] or [Value] defines a [Person]'s behavior. 
- PARTICIPATES_IN: A [Person] is involved in an [Action].

## DIRECTIONAL AGENCY & CONNECTIVITY RULES
1. THIRD-PERSON POV: Write all node names, descriptions, and relationship contexts in the THIRD PERSON. Use "Karen Miura" or "she/her/he/him" instead of "I/me/my". You have to maintain a neutral, clinical yet empathetic tone in all English descriptions.
2. MANDATORY RECIPIENT: Every [Action] or [Trigger] that involves interpersonal interaction MUST have a target. Link the Action to the recipient using [TARGETS] or [ACTS_UPON] (e.g., [Action: CONFESSION] --[ACTS_UPON]--> [Person: ALICE]).
3. NO ISOLATED NODES: Every node declared in the 'nodes' array MUST have at least one incoming or outgoing edge in the 'edges' array. If a person is mentioned but has no direct action, link them to the User via [MENTIONED_BY] or to the central Trigger via [PRESENT_DURING].
4. AGENCY CONTEXT: Ensure the graph explicitly reflects whether the User was the ACTIVE actor or the PASSIVE recipient of an action. This is critical for mapping the resulting relation.
5. OWNERSHIP: Every [InternalState], [Belief], or [Pattern] must be linked to its owner: (User/Person) --[EXPERIENCES/HAS]--> [Node].

## ONTHOLOGICAL & EVENT–TRIGGER MODELING RULES
1. Every real-world event MUST be modeled as an [Action].
2. A [Trigger] represents the subjective psychological impact of an [Action].
3. Every [Trigger] MUST originate from exactly one [Action] via:
   [Action] --[RESULTS_IN]--> [Trigger]
4. A single [Action] may produce different [Trigger] nodes for different individuals.
5. [Trigger] nodes MUST NOT exist without a source [Action].
6. When an event contains both behavior and emotional impact, it MUST be split into [Action] and [Trigger].
### EVENT–TRIGGER DISTINCTION RULE
- Every real-world occurrence MUST be represented as an [Action] (objective event layer).
- A [Trigger] MUST NOT exist independently; it must originate from an [Action].
- A [Trigger] represents the subjective psychological impact of an [Action] on a specific [Person].
- Therefore, every [Trigger] MUST be connected using: [Action] --[RESULTS_IN]--> [Trigger]

### SUBJECTIVITY CONSTRAINT
- A single [Action] may produce multiple [Trigger] nodes for different individuals.
- A [Trigger] is always person-relative, not globally defined.
- You MUST NOT assume that all observers experience the same [Trigger].

### NO ISOLATED TRIGGERS RULE
- Every [Trigger] MUST have exactly one incoming edge from an [Action] via [RESULTS_IN].
- If no clear [Action] exists, the system MUST infer or construct the most plausible minimal [Action].

### ACTION DECOMPOSITION RULE
- If an event contains both physical behavior and psychological impact, it MUST be split into:
  - [Action]: external, what objectively happened
  - [Trigger]: internal, how it impacted the subject
These MUST be connected via [RESULTS_IN]
